01

One question in seven sizes

Every circuit runs a scrambling block U, flips a “butterfly” qubit b, runs U backwards, probes qubit q, and repeats. The final ⟨Zq⟩ is a fourth-order out-of-time-order correlator. It stays near 1 if the disturbance at b has not reached q, and decays toward 0 once chaotic dynamics have spread it. It is the same workload as Google’s Quantum Echoes experiment.

Because U runs four times, a 10-layer block becomes a 40-layer circuit, and an exact 36-qubit statevector would need about 1 TB of memory. The hidden circuits lived on BlueQubit’s servers: I never saw their gates, only what the API returned.

Scoring was the squared correlation (corr²) with the true values. A method that shrinks every value by the same factor still scores perfectly; what costs points is getting the ranking and shape wrong. That fact shaped the whole strategy.

03

Calibrate on circuits with known answers

You cannot see the hidden answers, so a setting can only be trusted after it works on a look-alike small enough to solve exactly. I built four: the S3 sample, Y4 (25-qubit fSim grid), P3 (30-qubit Clifford + Rz grid with S3’s gate statistics) and P4 (30-qubit fSim grid, solved on BlueQubit’s free exact device).

  • Threshold matters for fSim circuits. On Y4, Pauli-path at δ = 1e-4 scored corr² 0.70; at the tightest threshold the server accepted, 0.99. Truncation mostly shrinks values toward zero, unevenly.
  • MPS is the wrong tool on grids. On P3 it reported −0.009 for a circuit whose true value is −0.47. Its corr² looks fine on six points only because it preserves the ranking.
  • G4-like circuits stay hard. Even the tightest settings shrink P4 values by 2–5×, with a few outright errors.
04

The two findings that moved the score

Finding 1

The GPU was 233× faster for the identical answer

One G3 circuit at δ = 3e-5 took 41 minutes on the CPU Pauli-path device and 11 seconds on pauli-path.gpu, both returning ⟨Z⟩ = −0.1085. A full 36-circuit sweep became minutes and about $7, instead of roughly 22 hours. Every later experiment depended on it.

Finding 2

Transpilation level 3: +320 points on G3, +200 on G4

The hidden circuits contain long runs of redundant single-qubit gates. Each one is another place the Pauli sum is rotated and truncated. Merging them with the simulator’s heaviest pre-processing pass means fewer truncation steps and less lost weight. My look-alike had been built with Qiskit’s optimiser, which had already merged those gates, so it hid the effect: a proxy must match the data’s quirks, including how its gates are written down.

05

Seeing the scrambling front on a chain

On a 1D chain, entanglement grows slowly, which is home turf for matrix product states. G1 (30 qubits) fit BlueQubit’s free exact device and scored full marks. For G2, MPS at bond dimension 128 ran in about seven minutes per circuit and scored 540 of 600.

The G2 profile shows the challenge’s “secret weak bonds” directly: qubits 12–21 keep high values because weak couplings shield them from both butterflies, at qubits 2 and 31, so the scrambling front never fully reaches them.

A χ = 256 run might have closed the last 10%, but the server estimated 13.5 hours per job and its cost reservation would have frozen the GPU queue.

06

What didn’t work

Extrapolating δ → 0

Richardson-style extrapolation from two thresholds made P4 worse (corr² 0.78 → 0.59).

A Pauli-weight cutoff

Capping string length to fit δ = 1e-5 in memory: the same circuits were still rejected.

Blending thresholds

Gains on P4 came from a single outlier circuit, which is noise.

Tighter δ on G4’s strongest circuits

Values grew 15–45% in magnitude with the last $1.40 of credit; the score stayed at 700.

Calibrate before you trust. Know what the metric rewards. Check the boring knobs. And treat the budget as part of the algorithm: a one-GPU-job queue, cost reservations and a $25 minimum balance shaped the plan as much as the physics did.
